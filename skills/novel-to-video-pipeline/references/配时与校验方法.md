# 配时与校验方法

> 用途：给每章分镜定"该配多长"，以及用脚本对全部成品做量化校验与返工验收。

---

## 一、配时原则

1. **段长固定 15 秒**。多轮实测验证过的生成单位，不引入新变量；每段内部固定 **5 个拍点：0–3s / 3–6s / 6–9s / 9–12s / 12–15s**
2. **只调段数**。段数 ＝ 本章需要"单独交代清楚"的事件数，**一段一事**
3. **一段必须自洽**：有起点画面（② 首帧）、有完整的一拍动作或一次信息交付、有可交接的末帧。塞两件事就拆段，半段空转就并段
4. **总时长按戏量定，不设硬上限**——时长服从"每拍 ≤3 件事、每拍台词 ≤18 字"这个下限，而不是服从某个"预告片式"的上限

### 承载量参考（判断该拆还是该并）

| 段落类型 | 15 秒承载量 | 超过则拆段 |
|---|---|---|
| 对话戏 | 4–6 条短台词（含动作贯穿） | >6 条 |
| 动作戏 | 1 组连续动作（出招 10 次以内） | >10 次 |
| 意象/闪回段 | 1 个完整意象序列 | 不与现实层戏合并 |

### 调整方向
- **要缩短**：优先并"信息段"（对谈、赶路、交代），**绝不并"高潮段"**（交手、反杀、异象首次出现）
- **要延长**：优先拆"动作超载段"（出招>10 次）与"信息超载段"（台词>6 条）

---

## 二、配时工作流

1. **通读章节原文**（按分卷文件行号定位）
2. **列事件清单**：数出这一章要"单独交代"的事件（入场/交手/揭底/收束…），一事一段
3. **台词做账**：全章台词字数 ÷ 总秒数 ≤5 字/秒（不达标则加段）；同时核对每一拍 ≤18 字
4. **写时长规划总表**：`| 章节 | 时长 | 段数 | 戏量 | 配时理由 |`
   - 配时理由写清：本章的戏量结构（几件事）、为什么是这个段数（哪一段是"下限"决定项）
5. 章节之间不搞一刀切——有的章 60 秒（单一空间情绪戏），有的章 150–180 秒（对白最密/多高潮），按戏量各自定

## 三、密度重排（量化返工法）

> 起因场景：初稿完成后逐段审核，发现大量段落"每拍行为过密"（实测约 37% 的拍超过 3 件事）。此时做全量重排。

**流程**：
1. **全量统计**：用查密度脚本扫全部成品，得到每份的：拍数、总事数、平均事每拍、最大事数、超 3 的拍数、建议段数
2. **定位**：按"超 3 的拍数"排序，从超载最重的一份开始
3. **扩段**：把塞满的段拆开，每拍摊到 ≤3 件事（末帧交代句不计）；段长仍是 15 秒
4. **复测**：每份改完立刻跑全部校验，全过才做下一份
5. **验收**：全批实测口径——
   - 结构 20/20（视频节＝段数、①—⑤＝5×段、末帧行＝段数、路线行＝段数）
   - 超 3 件事的拍 ＝ 0
   - 单拍台词超 18 字的拍 ＝ 0

**重排时的内容口径**：尺度与剧情**以原著为准**——补回被删句、解除被软化处、删掉新增情节（重排≠改写）。

## 四、校验脚本设计（"四把尺子"）

用脚本做确定性校验，不靠人工感觉。一体式脚本见 `../scripts/check_storyboard.py`；以下为原生 PowerShell 版的设计要点（可照此复刻）：

### 1. 查密度（每拍事数）
- 解析：扫描所有 `SC*.md`，文件名解析章号/秒数/段数；逐行匹配**拍点行**（`> **0–3s：**` 式）
- 事数算法：拍点行正文按 `[。；]` 断句，丢弃长度 ≤3 的碎片；行内含"末帧："时减 1
- 输出：`| 章 | 段 | 拍 | 总事数 | 均事每拍 | 最大 | 超3的拍 | 建议段数 | 建议秒数 |`
- 判读：本份那一行须满足 `段＝目标段数`、`最大 ≤3`、`超3的拍＝0`；`建议段数`计算式 `ceil(总事数÷2.4÷5)`

### 2. 查超线（每拍台词）
- 解析：拍点行内的引文（「…」式引号）
- 计数：引文内字数；**人工复核半截句**（脚本只统计"以句末标点结尾"或"紧跟『道／说／问…＋冒号』"的引文——不要靠这个漏洞，人工保证每一拍说出口的字数 ≤18）
- 判读：`超线：0`

### 3. 查台词（原文引语落点）
- 输入：章号；解析该章原文里的全部引语，逐句核对是否出现在**拍点行**里（对白表里写了不算）
- 拆到两拍的整句：两个拍点行各出现半截（人工确认）
- 判读：`全部 N 句都在拍点上`

### 4. 终检（配时＋结构＋服装词）
- 配时：文件名秒数/段数 vs 标题行一致
- 结构：视频节数＝段数；①—⑤块数＝5×段数；末帧行数＝段数；路线行数＝段数
- 服装词：词表命中数（本份一行必须为 0）

### 5. 一体式脚本（`../scripts/check_storyboard.py`）

Python 单文件、无依赖，一次跑完密度/台词/结构/服装词四类检查。相对"四把尺子"的关键口径设计：

- **台词双口径**
  - 完整句口径（FAIL 条件，对齐全量验收基线）：只统计"以句末标点结尾"或"前 18 字符窗口以动词＋可选冒号结尾"的引文——保证没有"一整句挤在一拍"。
  - 全量口径（默认 WARN，`--strict` 升级为 FAIL）：拍内全部口语引文合计（含半截句），自动排除心声/内白与舞台指示类引用——"说出口的字数"的物理上限，用于人工复核。
- **服装词分两级**
  - 生成层（`## 视频 N` 节内 = 直接投喂层）命中 → FAIL，必须为 0。
  - 说明层（导语/路线表/节标题等）命中 → WARN——多为原文引用与戏眼描述，人工确认。
  - 自动跳过声明行（含"不描述/禁用/严禁/不写"等标记）；引号「」、书名号《》、粗体 `**…**` 内的引用文字自动豁免（原文台词逐字保留）。
- **格式兼容**：多重 BOM 自动剥除；时间码后带括号说明（`**0–3s（过场）：**`）与 `**0–3s：正文**` 包裹变体均可识别；路线小节支持别名标题（如"XX路线"）；事数统计剥离引号内台词、豁免"（…不计…）"注释、"末帧"交代句减一。

用法示例：

```bash
python check_storyboard.py ./视频提示词              # 全目录
python check_storyboard.py SC101_*.md --beats        # 单份 + 每拍明细
python check_storyboard.py . --strict                # 全量台词口径升级为 FAIL
```

## 五、报告格式（返工交回）

报告 ≤10 行：
1. 新文件名
2. 校验脚本输出原文（逐条贴）
3. 按原文恢复/补回的清单（逐条：原文行号 ＋ 恢复了什么）
4. 跨文件重复等遗留说明

---

## 六、阶段检查点（全流程的质量闸门）

| 闸门 | 检查 |
|---|---|
| 角色库完成 | 廓形互斥总表覆盖全部主要角色；每份含【原文依据】/【设计补全】分级 |
| 素材库完成 | 索引表全；跨章复用表全；非写实层已隔离标注 |
| 配时完成 | 时长规划总表全；每章台词字数账 ≤5 字/秒 |
| 每份分镜完成 | 四把尺子全过（密度 0 超 / 超线 0 / 台词全落点 / 结构全对齐 / 服装词 0） |
| 全批完成 | 抽检跨文件重复；文件名与内容规格一致；旧版无残留 |
